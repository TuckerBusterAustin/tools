How to do an on-page SEO audit of a single page

An on-page SEO audit checks what is inside one page's HTML: the tags and structure that tell search engines and social platforms what the page is about. It doesn't cover backlinks, site speed or keyword research. Keeping the scope that narrow is what makes it quick and repeatable.

Here is a practical order to work in, what to look for at each step, and the mistakes that come up most often.

Step 0: Look at the HTML the crawler sees

Open the page and press Ctrl+U (Windows) or Cmd+Option+U (Mac), or type view-source: in front of the URL. That shows the HTML the server sent.

Pitfall: on JavaScript-heavy sites (React, Vue, some page builders), the raw source may not contain the title or meta tags, because scripts add them later. To see the final page, open DevTools (F12) and go to the Elements panel. If the two versions don't match, note it. It is a finding in its own right.

Step 1: Title tag

Find <title> inside <head>.

  • There should be exactly one, and it shouldn't be empty.
  • It should describe this page, not just the brand. Home | Acme tells nobody anything.
  • Put the important words first. Google doesn't publish a character limit, but long titles get cut off in results, so the start of the title is what people actually see.
  • Check that it isn't copied word for word from other pages on the site.

Google may show a different title than the one you wrote. Its title-link documentation says it draws on several sources, and since 2024 that includes the og:title tag. A clear, accurate <title> is still the strongest hint you control.

Step 2: Meta description

Look for <meta name="description" content="...">.

  • Is it there at all? Missing descriptions are very common.
  • Does it summarize this page in a sentence or two, in a way that makes someone want to click?
  • Is it unique to this page?

Google often writes its own snippet from the page text, so treat the description as your best pitch, not a guarantee.

Step 3: Headings

List the <h1> to <h6> tags in order (in DevTools, search the Elements panel for <h).

  • One clear <h1> that matches the topic of the page is the usual convention.
  • Headings should be in a logical outline. Watch for levels used only for font size, like an <h4> in the footer that reads "Follow us".
  • A page with no headings at all is hard to scan, for people and for parsers alike.

Step 4: Image alt text

Every <img> should have an alt attribute.

  • Content images: describe what the image shows, briefly (alt="Red trail running shoe, side view").
  • Decorative images: use an empty alt="" so screen readers skip them.
  • Pitfalls: a missing alt attribute, file names used as alt text (IMG_2041.jpg), or the same keyword stuffed into every image.

Step 5: Links

Go through the <a> tags.

  • Anchor text should say where the link goes. Flag "click here" and "read more".
  • Look for empty links: an <a> with no text and no image alt text.
  • Look for href="#" or javascript: links that are being used in place of real URLs.
  • Spot-check that important internal links point to live pages.

Step 6: Canonical tag

Look for <link rel="canonical" href="...">.

  • It should be an absolute URL (https://example.com/page/). Google warns that relative URLs can be misread.
  • It normally points to the page itself, unless the page really is a duplicate.
  • Common mistakes: it points to the homepage on every page, it uses http on an https site, or there are two canonical tags.

Google treats the canonical as a strong hint, not a command, so it can't fix a messy URL setup by itself.

Step 7: Viewport tag

Check for:

`html

<meta name="viewport" content="width=device-width, initial-scale=1">

`

Without it, phones render the page at desktop width and zoom out. A missing viewport tag usually means an old template.

Step 8: Open Graph tags

These control the preview card when someone shares the link on social platforms and in chat apps. Look for at least:

`html

<meta property="og:title" content="...">

<meta property="og:description" content="...">

<meta property="og:image" content="https://...">

<meta property="og:url" content="https://...">

`

Pitfall: an og:image with a relative path or an image that no longer exists. The share card then shows up blank.

Step 9: Rank what you found

A raw list of 20 issues isn't useful. Sort it:

1. High: things that break how the page is understood or shown. Examples: a missing or duplicate title, a canonical pointing to the wrong page, no viewport tag.

2. Medium: a missing meta description, no H1, many images without alt text, missing Open Graph tags.

3. Low: a long title, a vague anchor here and there, a skipped heading level.

Write each item as "what's wrong, and what to change", in plain words. "Add a meta description summarizing the pricing page" is something a client can act on. "Meta description: FAIL" is not.
