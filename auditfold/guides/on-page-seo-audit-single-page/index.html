How to do an on-page SEO audit of a single page

What an on-page audit covers

An on-page audit looks at what's inside the page's HTML: the tags and content that you or your client control directly. It doesn't cover backlinks, site speed or crawl budget across the whole site. Those are separate jobs. Auditing one page at a time is the quickest way to find problems on a page that matters, like a homepage, a key service page or a new landing page.

All you need is the page's HTML and the checklist below.

Step 1: Get the right HTML

Open the page, right-click and choose View Page Source (or press Ctrl+U / Cmd+Option+U). That shows the HTML the server sends.

Pitfall: on sites built with JavaScript, the source can be almost empty, because the content is added later in the browser. If so, open DevTools (F12), right-click the <html> element in the Elements panel and choose Copy > Copy outerHTML to get the rendered page. Note which version you audited. If important tags only appear after rendering, that's worth flagging on its own.

Step 2: Title tag

Find <title> in the <head>.

  • It exists, and there's only one. Missing or duplicate titles are common in templates.
  • It's specific to this page. Home or the bare brand name is a missed chance.
  • Length. Google cuts off titles by display width, not by a fixed character count. A common rule of thumb is roughly 50-60 characters so the important words show.
  • Front-load the topic. Emergency Plumber in Leeds | Smith & Co beats Smith & Co | Welcome to Our Website.

Step 3: Meta description

Look for <meta name="description" content="...">.

  • Check that it exists and is unique to this page.
  • Write it as a one- or two-sentence pitch for the click: what the page offers and why it's worth opening.
  • Keep in mind that Google often rewrites the snippet using text from the page, so the description shapes the snippet but doesn't control it. Its job is the click, not the ranking.

Step 4: Headings

List every <h1> to <h6> in order.

  • There should be an <h1> that says what the page is about.
  • Headings should form a sensible outline. Watch for jumps like <h1> straight to <h4>, or headings used only to make text big.
  • Pitfall: don't treat "more than one H1" as an emergency. Google has said multiple H1s aren't a problem. One clear H1 is still the tidiest convention, so flag extra H1s as low priority.

Step 5: Image alt text

Check every <img> for an alt attribute.

  • Images that carry meaning (products, diagrams, team photos) need alt text that describes them: alt="Copper pipe joint after soldering".
  • Purely decorative images should have an empty alt="", so screen readers skip them.
  • A missing alt attribute and an empty one aren't the same thing. Only the first is always a problem.
  • Avoid stuffing keywords into alt text.

Step 6: Links

Go through the <a> tags.

  • Look for empty or placeholder href values (href="#", href="").
  • Look for vague anchor text like "click here" or "read more" where a descriptive label would help.
  • Make sure the page links to related pages on the same site. A page with no internal links out is a dead end.
  • Note any rel="nofollow" on internal links. It's usually a mistake.

Step 7: Canonical tag

Look for <link rel="canonical" href="...">.

  • It should use an absolute URL that points to the preferred version of this page, usually itself.
  • Common bugs: every page's canonical points to the homepage (a template error), the canonical points to an http:// or staging URL, or there are two canonical tags.
  • Google treats the canonical as a strong hint, not an order, but a wrong one can still keep the page out of search results.

Step 8: Viewport tag

For mobile-friendly pages you need:

`html

<meta name="viewport" content="width=device-width, initial-scale=1">

`

If it's missing, phones show the desktop layout zoomed out. Google indexes the mobile version of pages, so this matters.

Step 9: Open Graph tags

These control how the link looks when it's shared on social platforms and in many chat apps:

`html

<meta property="og:title" content="...">

<meta property="og:description" content="...">

<meta property="og:image" content="https://...">

<meta property="og:url" content="https://...">

`

Missing og:image is the most visible gap, because shared links end up with no picture or a random one.

Step 10: Rank what you found

A list of 20 problems in random order is hard to act on. Sort them:

1. High: things that can keep the page out of search or make it look broken (missing title, wrong canonical, no viewport).

2. Medium: things that weaken the click or the page's clarity (weak or missing meta description, no H1, missing alt text on key images).

3. Low: polish (extra H1s, vague anchor text, missing Open Graph tags on a page that's rarely shared).
